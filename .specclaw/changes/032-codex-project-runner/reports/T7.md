# T7 — First-turn thread persistence

The installed Codex app-server returns a thread ID before creating a resumable rollout. A direct app-server probe showed `thread/resume` returns `no rollout found` after starting a thread with no turn. The adapter now saves a new thread ID only after the first `turn/start` succeeds. If the process stops before any turn, the next process starts a fresh thread without an invalid saved pointer.

Fake app-server tests cover the unused-thread restart and persistence after first delivery. A live isolated two-turn Codex smoke test confirms that a thread with a completed turn resumes and produces an MCP reply on the next turn.
