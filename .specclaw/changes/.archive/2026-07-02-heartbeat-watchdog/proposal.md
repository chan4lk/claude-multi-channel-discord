# Proposal: Heartbeat Watchdog

**Created:** 2026-06-19
**Status:** ✅ Approved

## Problem

Project channels accumulate stalled work — Claude asked the user a question, the user never replied, the subprocess got idle-evicted, and the task is forgotten. There is no mechanism today to surface these pending states to the operator or to automatically resume them. Work silently dies between sessions.

## Proposed Solution

Add a **heartbeat watchdog** that runs on a configurable schedule (e.g. every 30 min) on the master channel. On each tick it:

1. Scans all configured project channels
2. Reads each channel's transcript tail to classify state: `idle` / `waiting-on-user` / `stalled-mid-task`
3. Acts based on the channel's **mode**:
   - **supervised** (default): posts a summary to the master Discord channel — "channel X has been waiting 2h for user input: _last question_"
   - **autonomous**: injects a context-aware nudge (generated by master LLM from transcript summary) directly into the channel's Claude subprocess, no human required
4. Autonomous mode is per-channel, with an **expiry time range** (e.g. "autonomous 08:00–22:00") — outside the window it falls back to supervised

New infrastructure:
- `every Xm/Xh` interval syntax in the scheduler (currently daily HH:MM only)
- `mcp__mcd__inject(chatId, text)` MCP tool on the master server — lets master push text into another channel's subprocess
- Per-project `heartbeat` config block in `channels.json`
- `!project heartbeat` verb — runs one scan immediately (useful for testing)
- `!project set <slug> --heartbeat-mode autonomous --heartbeat-window 08:00-22:00` to configure

## Scope

### In Scope
- Interval scheduler syntax (`every 30m`, `every 1h`, `every 2h`)
- `mcp__mcd__inject` MCP tool (master injects into any channel subprocess)
- Per-channel heartbeat config: `mode` (`supervised`|`autonomous`), `window` (HH:MM-HH:MM), `staleAfterMinutes`
- `!project heartbeat [--channel <slug>]` master verb — immediate scan
- `!project set <slug> --heartbeat-mode <mode> [--heartbeat-window HH:MM-HH:MM]`
- Master CLAUDE.md updated with heartbeat commands
- Heartbeat scheduler entry in master: `!project schedule add heartbeat every 30m`

### Out of Scope
- Reading Discord message history for state detection (transcript-only for now)
- Cross-channel task handoff ("ask channel B to finish channel A's task")
- Push notifications outside Discord (email, SMS)
- Fine-grained task tracking (separate task state file per channel)

## Impact

- **Files affected:** 6–8 (scheduler.ts, master-mcp-server.ts, master-commands.ts, channels-config.ts, claude-process.ts, server.ts, templates/master.CLAUDE.md + tests)
- **Complexity:** medium
- **Risk:** medium — heartbeat injects messages into live subprocesses; wrong classification could spam channels in autonomous mode

## Decisions

1. **State classification**: both — unanswered `?` in Claude's last message AND `tool_use` block without matching `tool_result`
2. **Stale threshold**: 60 min global default, per-channel override via `staleAfterMinutes`
3. **Autonomous nudge text**: master LLM generates context-aware prompt from transcript summary
4. **Window timezone**: UTC
